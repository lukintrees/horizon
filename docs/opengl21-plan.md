# Horizon на OpenGL 2.1: план (цель — Radeon X1650)

План того, как сделать сборку Horizon, которая запускается и играется на железе уровня ATI Radeon
X1650 (R500, 2006–2007): OpenGL 2.1, GLSL 1.20, без compute, без массивов текстур, без UBO, без
инстансинга. Это не настройка и не флаг: сегодняшний рендерер физически не может работать на таком
контексте, и документ честно говорит, что придётся переписать, что переиспользовать и сколько это
стоит.

Проверено по коду на `8dbbde4` (main). Каждая цифра ниже — из этого дерева.

## 0. Короткий ответ

- **Реально ли это?** Да, но это отдельный, урезанный рендерер на ~1.2 тысячи строк GLSL 1.20 и
  ~8–12 тысяч строк Rust, плюс обвязка вокруг `Game`, плюс отдельная сборка под Windows 7 (или
  только Linux). Оценка (сводка в §10): **~3 месяца** до «запускается, меню, мир, можно ходить»
  (Phase 0–6 без оптимизаций и без Windows-сборки, Linux) и **~5–6 месяцев** до «играбельно с
  оговорками» на живом железе. Урезание по §6 и отказ от Windows в первой версии — единственный
  способ ускориться.
- **Почему нельзя просто включить OpenGL.** wgpu GL-бэкенд требует **GL 3.3 core** и жёстко
  отбрасывает всё ниже (`third_party/wgpu-hal/src/gles/adapter.rs:266`); naga умеет только GLSL
  330+ (`third_party/naga/src/back/glsl/mod.rs:7-15`), а тест репозитория проверяет переводы лишь
  для 330 и 400 (`crates/horizon-client-render/src/gfx.rs:11217`). Минимум уже заявлен публично:
  README и роадмап (`opengl-fallback`, v0.2.63) обещают «OpenGL 3.3 core».
- **Почему нельзя патчить wgpu-hal вниз до 2.1.** Пришлось бы эмулировать внутри HAL массивы
  текстур (через атласы), UBO (через `glUniform*` с рефлексией), инстансинг, целочисленные
  атрибуты и VAO. Это исследовательский проект дороже варианта «свой рендерер» и с худшим
  результатом.
- **Что переиспользуется почти без изменений:** все данные кадра и мира. `Frame`, `SectionMesh`,
  `TerrainVertex`, `HudBatch`, `entity_batch`, мешер, LOD, стриминг, освещение, физика, HUD-логика —
  в них нет `wgpu` вообще. Это и есть главный аргумент, что план выполним.
- **Что переписывается:** `gfx::Renderer` (11.8k строк, 79 публичных методов), 29 WGSL-файлов
  (5.4k строк), окно/поверхность/контекст, и обвязка `Game` (164 места вызова `renderer.` в
  `crates/horizon-client/src/game.rs`).
- **Отдельная проблема, без которой план не имеет смысла:** X1650 не имеет драйвера под Windows 10
  (последний Catalyst для R500 — 9.3, Windows XP/Vista/7), а Rust с 1.78 требует Windows 10 для
  tier-1 целей. Значит, Windows-сборка — это `x86_64-win7-windows-msvc` (tier 3, nightly +
  `-Z build-std`). На Linux всё проще: `r300g` в Mesa до сих пор даёт ровно **GL 2.1** для R500,
  поэтому **Linux — основная цель для проверки**.

## 1. Цель и критерий готовности

Целевая машина (по реальному отчёту карты, см. §9.1):

| Параметр | Значение X1650 (R500, RV530/RV560) |
| --- | --- |
| OpenGL | **2.1** (GL 3.0 — 38 %, GL 3.3 — 0 %) |
| GLSL | **1.20** |
| Max texture size | 4096 |
| Max texture array layers | нет массивов (это GL 3.0) |
| Max native attributes | 10 (жёсткий лимит `GL_MAX_VERTEX_ATTRIBS` = 16) |
| Max draw buffers | 4 (через `ARB_draw_buffers`) |
| Uniform buffers (UBO) | нет (GL 3.1) |
| Instancing | нет (`ARB_draw_instanced` — GL 3.0) |
| Compute | нет (GL 4.3) |
| Vertex texture fetch | **нет** (R500 не имеет текстурных блоков в VS) |
| Dynamic uniform indexing в VS | **нет** («Max Native Address Registers: 0») |
| ALU инструкций (нативные) | VS 512, PS 512 / индирекций текстур 128 |
| FBO | есть (`GL_ARB_framebuffer_object`) |
| Anisotropy | 16 |

Критерий готовности «v0 — запустилось» (Phase 2): окно, главное меню, экран настроек, звук, вход в
мир, HUD и текст — на 1024×768, 30 FPS в меню.

Критерий готовности «v1 — играбельно» (Phase 6): одиночный мир, 4–6 чанков прорисовки, 20 TPS,
25–30 FPS в лесу днём, блоки ставятся и ломаются, мобы, предметы, инвентарь, сохранение. Без
пакетов шейдеров, без LOD, без HDR, без генерации кадров, без OIT.

## 2. Что именно блокирует сегодня (карта гейтов)

Найдено по коду; это и есть список того, что нужно обойти.

| Блокер | Где | Чем обходим на GL 2.1 |
| --- | --- | --- |
| Контекст GL 3.3 core обязателен | `third_party/wgpu-hal/src/gles/adapter.rs:266` | Свой контекст (glutin) + прямой GL |
| GLSL только 330+ | `third_party/naga/src/back/glsl/mod.rs:7-15` | Рукописные шейдеры на GLSL 1.20 |
| Массивы текстур (`texture_2d_array`, 8 сэмплеров `sprites..sprites_7`) | `src/terrain.wgsl:46-57`, `gfx.rs:1255-1290` (`SPRITE_SPLIT` 2048) | Один (или 2–4) плоских атласа 2D; UV абсолютные |
| Storage-буферы (арена секций, `arena_page`, `slot_origins`) | `src/terrain.wgsl:338-407` | Одна VBO + `glUniform` со смещением секции; без арены |
| Компактный (packed) формат квадов с битовой распаковкой | `src/mesher/packed.rs:1-22`, `gfx.rs:30-31` | `pack_quads(false)`: обычные вершины (хук уже есть) |
| Целочисленные атрибуты (`Uint16x2`, `Uint16`, `Uint8x2`, `Uint32`) | `gfx.rs:30-31` (terrain), `gfx.rs:3239` (entity) | Конвертация в float/normalized на CPU при загрузке меша |
| UBO (`struct Globals`, 20+ полей с массивами) | `src/terrain.wgsl:2-46`, `gfx.rs:335` | Плоские `glUniform*`; массивы `dynamic_lights`/`colored_lights`/`emissive_layers` — вырезать |
| Инстансинг (`VertexStepMode::Instance`, origin секции) | `gfx.rs:2386-2390`, `3252-3256` | Отдельный draw на секцию, origin — в uniform |
| Compute-шейдеры (culling, animация спрайтов, скины, flatten, frame gen) | `src/gfx/{gpu_culling,animate,entity_skin,flatten}.wgsl` | Всё уже опционально: CPU-анимация спрайтов есть (`sprites.rs:14`), culling CPU есть (`occlusion.rs`) |
| Indirect draw / multi-draw | `src/gfx/arena.rs`, `flat.rs` | Не нужен: draw на секцию |
| VAO, sampler objects, `glTexStorage` | по всему `gfx.rs` | Указатели атрибутов на каждый draw; `glTexParameteri` + `glBindTexture` |
| `textureSampleGrad` (RGSS/aniso-фильтрация) | `src/terrain.wgsl:67-95` | Отключить: обычные производные, режим `textureFiltering=0` |
| Битовая арифметика в шейдере (`>>`, `&`, `bitcast`) | `src/terrain.wgsl:233-430` | Не нужна при `pack_quads(false)`; остатки — на float |
| MRT (motion vectors) — есть `@location(1)` | `src/gfx/frame_gen/motion.wgsl:22` | Генерация кадров отсутствует на этом пути |

Важное наблюдение: **рендерер уже умеет деградировать**. В `gfx.rs` опциональны culling, GPU-фрейм,
visbuffer, OIT, HDR, shader packs, анимация на GPU (`gfx/animate.rs:274-288` явно проверяет
compute и уходит на CPU). Не хватает ровно того слоя, который *обязателен*: поверхность, шейдеры,
буферы, атлас, draw-вызовы. Поэтому план — не «переписать всё», а «заменить обязательный слой».

## 3. Варианты архитектуры

### Вариант A (рекомендуется): отдельный рендерер `gl21` за общим интерфейсом

Новый модуль `crates/horizon-client-render/src/gl21/` (окно/контекст, ресурсы, 8 шейдеров,
батчи) и фасад `enum Renderer { Wgpu(gfx::Renderer), Gl21(gl21::Renderer) }` с тем же набором
методов, что `Game` вызывает сегодня (79 публичных + поля `config`, `device`, `screenshot` и т. п.).

- Плюс: не трогает работающий путь wgpu (никаких регрессий у 99 % игроков), честные оценки, можно
  выпускать как отдельную сборку/ветку, легко удалить, если не взлетит.
- Минус: два рендерера живут параллельно; фасад нужно аккуратно расширять (часть полей
  `pub` в `Renderer` используется игрой напрямую — их придётся превратить в методы).
- Объём: ~8–12k строк Rust + ~2–3k GLSL, из них ~60 % — перенос уже написанной логики
  (атлас, HUD-батчи, entity batch, раскладка кадра), а не новые алгоритмы.

### Вариант B: патч wgpu-hal GL до 2.1

Эмулировать в HAL массивы текстур, UBO, инстансинг, целочисленные атрибуты и VAO.

- Минус: это форк размером с сам HAL, ломает семантику (текстурный массив нечем выразить так,
  чтобы шейдер об этом не знал), требует рефлексии шейдеров для UBO→uniform, и всё равно не
  решает GLSL 1.20 (naga). Оценка в 2–3 раза больше варианта A. Не рекомендуется.

### Вариант C: программный рендер (llvmpipe / ANGLE D3D9)

- llvmpipe на Athlon 64 X2 даст 2–5 FPS на 1024×768 — годится только как режим диагностики
  («игра запустилась, картинка есть»), не как игра. Можно оставить как аварийный fallback.
- ANGLE с D3D9-бэкендом мёртв и не даёт нужного GL.

**Решение: вариант A**, с C как необязательной страховкой в конце.

## 4. Фазы

Оценки — в человеко-неделях для одного разработчика, знакомого с кодовой базой; параллелятся
слабо (всё упирается в один рендерер).

### Phase 0 — фундамент и проверяемость (1 неделя)

1. `docs/opengl21-plan.md` (этот файл) + профиль железа в машинночитаемом виде:
   `crates/horizon-client-render/src/gl21/profile.rs` — константы X1650 (GL 2.1, GLSL 120,
   max texture 4096, нет массивов/UBO/инстансинга/compute/VTF, 4 draw buffers, 16 атрибутов).
2. Режим «притвориться X1650»: `HORIZON_GL_PROFILE=x1650` — заставляет *существующую*
   детекцию возможностей (`gfx.rs:4077`, `gfx/cull.rs:207`, `gfx/animate.rs:278`,
   `gfx/flat.rs:212`, `gfx/visbuffer.rs:31`) идти по самым бедным путям на любой машине. Это
   даёт CI-проверку деградаций без железа.
3. Харнесс `tools/gl21_shaders.py`: каждый GLSL-файл пути GL 2.1 парсится `naga::front::glsl`
   (фича `glsl-in` уже включена в `horizon-client-render`) и валидируется с
   `Capabilities::empty()`. Плюс запрет запрещённых конструкций текстовым грепом: `#version` не
   120, `uniform block`, `layout(`, `in ` / `out ` на верхнем уровне, `texture(`/`textureLod(`,
   `flat`, операторы `<<`, `>>`, `&`, `|`, `bitcast`, `gl_VertexID`, `gl_InstanceID`,
   `texture2DArray`, `imageLoad/Store`, `atomic*`.
4. Скелет crate-фичи: `gl-legacy` (собирается только с ней), чтобы обычные сборки не тянули
   glutin и не ломались.

Выход: гейты описаны, харнесс зелёный на пустом наборе, ничего в игре не меняется.

**Сделано (phase 0):** `crates/horizon-client-render/src/gl21/` — профиль карты (`profile.rs`,
`Profile::X1650`) и переключатели (`HORIZON_GL_PROFILE`, `HORIZON_GL21_PATHS`), которые на любой
машине включают самые бедные пути существующего рендерера (CPU-анимация спрайтов, без occlusion
culling, без flat draws, без translucent batching, без GPU-culling, без OIT, без visbuffer, без
компактного формата квадов, одна текстурная аррай-полоса). Линтер шейдеров —
`tools/gl21_shaders.py` (+16 тестов в `tests/test_gl21_shaders.py`) и первые два GLSL 1.20 файла
(`gl21/present.vert`, `gl21/present.frag`). Как это запускать и что именно выключается:
[gl21-paths.md](gl21-paths.md).

### Phase 1 — окно, контекст, цикл (1–2 недели)

1. Контекст GL 2.1: `glutin` (0.32) — WGL на Windows, GLX/EGL на Linux; профиль
   *compatibility*, версия 2.1; загрузчик — `glow` 0.17 (уже в `Cargo.lock` через wgpu-hal).
   Требования: `GL_ARB_framebuffer_object` (FBO), `GL_ARB_occlusion_query` (опционально),
   `GL_ARB_draw_buffers` (опционально), `GL_EXT_texture_lod_bias`.
2. Swap: `SwapIntervalEXT` (vsync), ограничитель кадров — переиспользовать `clock.rs`/`frame_limiter`.
3. Сообщения об ошибках по-человечески: «нужен OpenGL 2.1 и FBO; у вас X», без падений.
4. Окно: `winit` уже используется (`crates/horizon-client-input/src/window.rs`) — не менять.

Выход: окно, чистый цвет, vsync, FPS в логе, корректный выход.

### Phase 2 — 2D: атлас, шрифты, HUD, меню (2–3 недели)

Это то, что даёт «игра запустилась».

1. **Атлас спрайтов без массивов.** Сейчас блок-спрайты живут в `texture_2d_array` (2048 слоёв
   на массив, до 8 массивов). На GL 2.1:
   - переупаковать слои в плоский атлас 4096×4096 (16×16 спрайтов по 256 px) или 4 атласа;
   - `TerrainVertex` для GL-пути несёт **абсолютные** UV (f32 или u16 с ценой точности — см.
     §5.2) и id атласа вместо `layer`;
   - переиспользовать уже готовые цепочки мип-уровней (`gfx.rs:1446-1490`, `MipmapGenerator`) и
     упаковку страниц (`gfx/pack_atlas.rs`), с другим «раскладчиком» на выходе.
2. HUD: `HudBatch` (`hud.rs:1473`) → одна VBO, 5 атрибутов, `glBlendFunc` по `Blend`-ранам
   (`Alpha`, `Invert`, `Additive`, scissor) — логика батчинга переиспользуется целиком,
   `hud.wgsl` переносится на GLSL 1.20 (~110 строк, без массивов).
3. Шрифты: атлас глифов через `glTexSubImage2D` (патчи уже формируются, `font::Patch`).
4. Экраны: `screen.wgsl` (~69 строк), `menu_blur.wgsl` (~32) — размытие меню можно отключить
   флагом на первый релиз, чтобы сократить объём.
5. Панорама титульного экрана: `gfx/panorama.wgsl` (30 строк) — кубическая карта, GL 2.1 умеет.

Выход: титульный экран, все меню, настройки, ввод текста, чат, инвентарь — без 3D-мира.

### Phase 3 — мир: terrain, небо, вода (3–4 недели)

1. Шейдер `terrain.wgsl` (940 строк) → `gl21/terrain.glsl` (~350–450 строк):
   solid, cutout (alpha test через `discard`), translucent, far tiles (LOD — только если
   решим оставить, см. §6), небо (`vs_sky`, sunrise fan), звёзды, контуры, debug-линии.
2. Формат вершины для GL: position f32×3, uv f32×2, light u16×2 как `NormalizedUint16`,
   color `Unorm8x4`. Stride ~32 байта вместо 24 — на 4–6 чанках это единицы мегабайт.
3. Рисование: один VBO-арена на страницу + draw на секцию с `glUniform3f(origin)`; сортировка
   прозрачного на CPU (уже есть, `translucency.rs`).
4. Occlusion culling: CPU-версия (`occlusion.rs`), опционально `ARB_occlusion_query` для
   «фаз 2».
5. Fog, lightmap, туман воды, небо, облака (`clouds.rs` — геометрия уже CPU), погода
   (`weather.rs` + `entity.wgsl`'s `vs_weather`).

Выход: `scene_replay` рисует захваченную сцену на GL 2.1 и совпадает с эталоном на 95 %+ (см.
§7 про эталоны).

**Сделано (phase 1–3, чистые данные и шейдеры — окна и контекста ещё нет):**

- `gl21/atlas.rs` — плоский атлас вместо `texture_2d_array`: квадратный, сторона — степень
  двойки, `rect(layer)` даёт `u_sprite` (`u0,v0,u1,v1`), `blit` копирует слой построчно.
  **Заполнения (padding) пока нет** — §5.2 требует его и укороченную цепочку мипов до того, как
  атлас попадёт в сборку: верхние мипы сейчас читают через шов соседнего спрайта.
- `gl21/vertex.rs` — вершина GL 2.1: `pos f32×3`, `uv f32×2`, `light u16×2` (normalized),
  `color u8×4`, шаг 28 байт вместо 32 из §5.2: слой спрайта не нужен отдельным атрибутом, его
  несёт прогон (`Batches::of` режет список вершин по спрайту, один draw на спрайт на секцию).
  Две поправки к §5.2, найденные при порте: normalized-`u16` приходит в шейдер как `n / 65535`,
  поэтому байт света пишется как `n * 257`; альфа вершины на wgpu несёт код эмиссии HDR
  (`mesher::emitting`), которого на этом пути нет, поэтому здесь она несёт флаг force-opaque
  (старший бит слоя) — именно это проверяет `solid_color`.
- `gl21/terrain.vert` / `terrain.frag` — порт `terrain.wgsl` на GLSL 1.20: solid, cutout и
  translucent одним шейдером, порог альфа-теста — uniform (`Pass::alpha_test`: 0.5 как в
  `solid_color`, 0.01 как в `fs_translucent`), лайтмап в том же порядке (`block` по x, `sky` по
  y), туман по двум расстояниям, вплывание секции (fade-in) через uniform.
- `gl21/draws.rs` — план кадра без GPU: небо, затем solid в порядке списка, затем прозрачное
  от дальнего к ближнему, затем present; `draw_calls` считает вызовы (на 2006 CPU это и есть
  цена), `Pass` знает про глубину, блендинг и порог теста.
- `gl21/context.rs` — чеклист §9.2 как данные: `Capabilities::missing()` («нужен OpenGL 2.1,
  драйвер сообщает 1.4») и `wanted()` (только скорость).
- `gl21/arena.rs` — один буфер вершин на весь обзор и диапазоны для `glBufferSubData` на кадр.
- `gl21/program.rs` — таблицы атрибутов и uniform'ов, сверяемые с объявлениями в самих шейдерах.
- **Собрано в CI:** `checks`/`verify` зелёный — `cargo fmt --check`, `clippy --workspace
  --all-targets -D warnings`, `cargo test --workspace`. Ничего из этого ещё не рисует: драйвер окна и
  контекста (Phase 1) требует `glutin`, которой в `Cargo.lock` нет.

### Phase 4 — сущности и всё остальное в мире (3 недели)

`entity.wgsl` (578 строк) → GLSL 1.20: модель, скиннинг, свет, glint, молния, облака,
погода, name tag'и, outline (glowing), разрушение блока, рука/предмет, тени сущностей (пятна),
частицы (батчи уже CPU: `particles.rs`), блочные сущности (`block_entity_render.rs`,
`static_entity.wgsl`, 21 строка).

### Phase 5 — постобработка и вспомогательное (1–2 недели)

`world_post.wgsl` (FXAA/copy), `screen.wgsl`-эффекты, скриншоты (`readback.rs` → `glReadPixels`),
`border.wgsl` (world border), `post_chain.wgsl` (эффекты зелий: invert, spiderclip, convolve),
`hdr.wgsl`/`hdr_stats.wgsl`/`oit*.wgsl`/`frame_gen/*`/`visbuffer.wgsl`/`gfx/pack_*.wgsl` —
**не переносятся**, соответствующие настройки на GL-пути серые и выключены.

### Phase 6 — интеграция в игру (2 недели)

1. `enum Backend` в `Renderer`-фасаде; выбор в настройках (Graphics API → «OpenGL 2.1»), плюс
   автовыбор, если GL 3.3 нет, а 2.1 есть: сегодня `backend_order` (`gfx.rs:1636-1650`) отдаёт
   `GL`, который на такой машине просто не откроется — нужен явный follow-up.
2. 164 места `renderer.` в `game.rs` — сначала завести фасад с методами-обёртками (auto через
   `grep`), затем чинить по одному: `config`, `device`, `screenshot`, `release_surface`,
   `recreate_surface`, `set_pass_timing`, `gpu_census` и т. п.
3. Экран настроек: на GL-пути показать реальные ограничения (RD ≤ 6, presets = Performance,
   shader packs/LOD/HDR/frame gen — недоступны), а не молча выключать.
4. Сообщение в лог и в телеметрию (`telemetry::set_gpu`) о бэкенде `OpenGL 2.1 (GLSL 1.20)`.

### Phase 7 — производительность на целевом железе (2–3 недели, нужен хотя бы один живой X1650)

1. Draw-call бюджет: 1 вызов на секцию → RD 4 даёт ~17×17×(24/16) ≈ 400–500 вызовов, RD 6 —
   ~900–1100. На одном ядре Athlon 64 это уже предел; телеметрия покажет, где упирается.
2. Кэш шейдеров на диске (у Catalyst 9.3 компиляция GLSL медленная; у Mesa — быстрая).
3. Обрезка ALU в шейдерах (`#ifdef`: без dynamic lights, без colored lights, без emissive
   layers, без `sunrise_fan`) — «Max Native ALU 512» не резиновый.
4. CPU: 20 TPS при RD 4–6 (генерация и мешинг — уже отдельные потоки; на 2 ядрах это половина).
5. Ограничитель памяти: 256–512 МБ VRAM; текстурный бюджет — атлас 4096×4096 RGBA = 64 МБ +
   мипы ≈ 85 МБ, это уже половина VRAM → 2 атласа 2048×2048 (по 16 МБ с мипами) как аргумент
   в пользу меньшего размера спрайта (128 px вместо 256).

### Phase 8 — сборка, распространение, документация (2 недели)

1. **Windows 7**: цель `x86_64-win7-windows-msvc` (tier 3, nightly + `-Z build-std`, либо
   пин Rust ≤ 1.77 для этой сборки). Проверить импорты (`dumpbin /IMPORTS`) на API Windows 8+;
   в репозитории уже есть прецедент такой работы (патч mimalloc из-за POPCNT, `#7264`).
2. **Linux**: основная цель; `r300g` + Mesa; проверить, что launcher не требуется — запуск
   `horizon-client` напрямую (см. п. 3).
3. **Launcher не запустится** на таком железе: он на GPUI + wgpu. Нужен либо «лёгкий режим»
   лаунчера на GL 2.1, либо CLI-путь: `horizon-client --launch` с готовым профилем/аккаунтом.
   Это отдельная задача на 1–2 недели, без неё игрок не войдёт в аккаунт.
4. **Подготовка ресурсов** требует JDK 25 (`horizon-prepare`, экспортёры на Java), а JDK 21+
   не работает на такой ОС/32-битной машине. Варианты: подготовка на другой машине и перенос
   папки `.local/horizon-client/26.3`, либо ждать «подготовку без Java» (issue #1750 в роадмапе).
   Это блокер уровня «игрок не сможет подготовить файлы», его надо решать в том же релизе.
5. Документация: `docs/known-issues.md` (что недоступно), README (новое требование
   «Vulkan, DirectX 12, OpenGL 3.3 или OpenGL 2.1 (сборка Legacy)»), страница установки.

## 5. Технические детали

### 5.1 Шейдеры: что переводится тяжелее всего

| Возможность WGSL | GLSL 1.20 | Решение |
| --- | --- | --- |
| `texture2DArray` + `layer` в вершине | нет | плоский атлас, UV абсолютные |
| `textureSampleGrad` | нет (нужен `ARB_shader_texture_lod`/`EXT_gpu_shader4`) | отключить RGSS/aniso-режим, аппаратные производные |
| целочисленная арифметика, биты | нет (1.30) | не нужна при `pack_quads(false)`; остатки — `floor`/`mod` на float |
| `flat`-интерполяция | нет | передавать одинаковые значения во всех вершинах квада, либо считать в фрагменте |
| `@builtin(vertex_index)` для полного экрана | нет | quads через 4 вершины из VBO (маленькая VBO `[0,0],[1,0],[0,1],[1,1]`) |
| uniform-структуры с массивами | частично (массивы есть, но VS без динамической индексации) | только скаляры/векторы; массивы — либо константы препроцессора, либо убрать |
| `discard` | есть | cutout как есть |
| MRT | `gl_FragData[]` через `ARB_draw_buffers` | не нужно |
| `override`-константы (pipeline constants) | нет | `#define` + перекомпиляция вариантов при старте (кэш обязателен) |

Оценка объёма перевода по файлам: `terrain.wgsl` 940 → ~400; `entity.wgsl` 578 → ~260;
`hud.wgsl` 125 → ~110; `screen.wgsl` 69 → ~60; `world_post.wgsl` 133 → ~110; `border.wgsl` 35 →
~30; `hdr.wgsl`/`post_chain.wgsl` → частично (эффекты зелий); остальное — не переносится.
Итого ~1100–1300 строк GLSL.

### 5.2 Форматы данных

- `TerrainVertex` сейчас 24 байта с `u16`-UV (1/32768 доли спрайта) и `layer`. Для GL-пути:
  `pos f32×3`, `uv f32×2` (абсолютные по атласу), `light NormalizedUint16×2`,
  `color Unorm8×4` = 32 байта. Точность f32-UV — далеко за пределами 1/4096.
- `entity_batch::Vertex` уже float-основанный, но содержит `Uint32` (layer с битами OIT/HDR) и
  `Uint8x4`/`Snorm8x4`. На GL-пути: `layer` → float, биты HDR/OIT из него вырезаются (их не
  используем), остаётся 6 float-атрибутов — влезает в 16.
- Никогда не превышать 16 атрибутов на draw (X1650: 16, из отчёта «native 10» — это другое).

### 5.3 Контекст и совместимость

- Запрашивать **compatibility**-профиль: `gl_FragColor`, `varying`, `attribute` — иначе на
  старых драйверах получите core 3.2 без нужных функций.
- VAO: `GL_ARB_vertex_array_object` есть у Mesa r300, но не гарантирован на Catalyst 9.3 →
  указатели атрибутов выставлять при каждом draw (дешевле, чем кажется, при <1000 вызовов).
- `glTexImage2D` вместо `glTexStorage2D`; NPOT: R300/R500 не умеют мипмаппинг NPOT
  (ограничение `LimitedNPOT`) → все атласы строго степени двойки, спрайты внутри — как сейчас.
- FBO: обязательно (`GL_ARB_framebuffer_object`), нужен для скриншотов и постобработки.
- Vsync: `wglSwapIntervalEXT`/`glXSwapIntervalEXT`; при отсутствии — ограничитель кадров.

### 5.4 Что выключается на этом пути (и как это показать игроку)

Пакеты шейдеров (`horizon-shaders`), LOD/дальний план (`lod.rs`), HDR (`gfx/hdr.rs`),
генерация кадров (`gfx/frame_gen.rs`), OIT (`gfx/oit.rs`), visbuffer (`gfx/visbuffer.rs`),
GPU-culling (`gfx/gpu_culling.rs`), translucent batching (`gfx/arena.rs`), CIT-глинт
(`hud.wgsl:54-65`), TAA/апскейл (`gfx/world_post.rs:257`), MSAA. Настройки на GL-пути должны
показываться как недоступные с причиной, а не пропадать: иначе игрок думает, что сломалось.

## 6. Что можно сократить, чтобы дойти быстрее

Порядок урезания (сверху — режем первыми):

1. LOD/дальний план — главный пожиратель памяти и ALU на такой карте.
2. Размытие меню, панорама (статичная картинка), анимация облаков.
3. Частицы сцены/погода (дождь можно, снег — упростить).
4. Тени сущностей (пятна) — можно выключить.
5. Сложные световые эффекты (`dynamic_lights`, `colored_lights`, `emissive_layers`) — вырезать
   препроцессором (это же и ALU-облегчение).

Нельзя резать: HUD, чат, инвентарь, сущности, блоки, свет, сохранение — без них это не игра.

## 7. Как проверять без X1650 (это ключ к плану)

1. **Профиль.** `HORIZON_GL_PROFILE=x1650` заставляет детекцию возможностей идти по бедным путям
   на любой машине (включая llvmpipe в CI). Это регрессионная сеть для «полу-рендерера».
2. **Статическая проверка шейдеров.** `tools/gl21_shaders.py`: `naga::front::glsl` парсит файлы
   с `Capabilities::empty()`; плюс грепы на запрещённые конструкции (§Phase 0). В CI — дешёво.
3. **Реальный GLSL-компилятор.** Добавить в CI необязательный шаг с `glslangValidator` (пакет
   `glslang-tools`) — он валидирует `#version 120`, и ловит то, что naga-glsl-in пропускает.
4. **Запуск на llvmpipe в контексте 2.1.** `MESA_GL_VERSION_OVERRIDE=2.1COMPAT
   MESA_GLSL_VERSION_OVERRIDE=120` + отключение расширений (`MESA_EXTENSION_OVERRIDE=-…`) даёт
   «почти» нужный контекст: драйвер всё ещё умеет больше, но наш код обязан идти по бедному
   пути. Это то, на чём можно гонять headless-тесты (`--offscreen`, `scene_replay`).
5. **Эталоны изображения.** `gfx/capture.rs` + `scene_replay` уже умеют воспроизводить сцену.
   Добавить сравнение «wgpu-эталон vs gl21» по SSIM с порогом (в репозитории есть заготовки
   скриншотов — `hud.rs`/`capture`), чтобы Phase 3–5 имели объективный критерий.
6. **Живое железо.** Нужен **один** ноутбук/десктоп с X1650 (или R300/R400 — та же ветка) под
   Linux с текущей Mesa: `r300g` даёт ровно GL 2.1. Плюс, для Windows-проверки, машина с Win7 —
   без неё Phase 8 вслепую.
